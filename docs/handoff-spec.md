## 0. คำสั่งเริ่มต้นสำหรับ AI

> สร้างระบบนี้เป็น **โปรเจกต์ static site + API proxy ตัวเล็ก + content pipeline** ไม่ใช่เว็บแอปใหญ่ ไม่มีฐานข้อมูล ไม่มีระบบล็อกอิน
> **ยึด `prototype-artifact.html` เป็นต้นแบบทุกด้าน** ทั้งดีไซน์ (สี ฟอนต์ ระยะ) โครงสร้างบท (เนื้อหา → หน้าต่างสู่จักรวาล → พุทธพจน์ → ลองมองรอบตัว → คำถามที่มักเกิด) ระบบศัพท์ และ **สำเนียงการเขียนเนื้อหา** — บทที่ 1–2 ในต้นแบบคือมาตรฐานคุณภาพที่ทุกบทต้องเทียบเท่า
> หัวใจของงานอยู่ที่ **ส่วนที่ 9 (Business logic)** โดยเฉพาะ 9.1 กฎการเรียบเรียงเนื้อหา, 9.3 กฎการตอบของผู้ช่วย AI และ 9.4 การเลือกบริบทส่งให้ AI — ห้ามเดา ห้ามลดทอน
> **ต้องเป็น Mobile Responsive เต็มรูปแบบ** ตามส่วนที่ 5 ผู้ใช้ส่วนใหญ่จะเปิดจากมือถือ ทุกหน้า ทุก interactive ต้องใช้งานได้ด้วยนิ้วบนจอ 360px
> Framework แนะนำ: หน้าเว็บเป็น **Vanilla HTML/CSS/JS** (ต่อยอดจาก prototype ได้ตรงที่สุด ไม่ต้องมี build step) หรือ Vite + vanilla ถ้าต้องการแยกไฟล์; API proxy ใช้ **Node.js 20 + Hono** (หรือ Express); pipeline ใช้ **Python 3.11** (pdftotext/pymupdf + Anthropic SDK); รันด้วย **Docker Compose** บน Ubuntu server ที่บ้าน เข้าถึงผ่าน Tailscale
> ทำเป็นเฟส: **เฟส 1 = เล่มแรกครบ 9 บท + โครงทั้งหมดใช้งานได้บน Tailscale** (เอกสารนี้ครอบเฟส 1) เฟส 2 = อีก 8 เล่ม + deploy สาธารณะ

## 1. ภาพรวมระบบ

แพลตฟอร์มเรียนรู้หนังสือชุดธรรมะ-วิทยาศาสตร์ 9 เล่ม (เล่มแรกคือ *ไตรลักษณ์ในควอนตัม* โดย สิรวิชญ์ รัตน์จินดา) สำหรับ **คนทั่วไปที่ไม่มีพื้นฐานทั้งธรรมะและวิทยาศาสตร์** เป้าหมายคือให้เข้าใจลึก น่าสนใจ และ **ถามข้อสงสัยได้ทุกจุดทันที** ผ่าน 3 ชั้น: (1) เนื้อหาเรียบเรียงใหม่ภาษาคนธรรมดา + ภาพเคลื่อนไหวโต้ตอบได้ (2) ศัพท์กดอ่านได้ทันทีโดยไม่ต้องรอ AI + ผู้ช่วย AI ที่รู้เนื้อหาทั้งชุด (3) แบบฝึกโยงกลับสู่ชีวิตจริง

ผู้ใช้เฟส 1: เจ้าของระบบและครอบครัว ผ่าน Tailscale. เฟส 2: บุคคลทั่วไปผ่าน Cloudflare Pages

**เหตุผลที่ไม่ใช่ HTML ไฟล์เดียวเหมือน prototype:** 9 เล่ม ≈ 80 บท แก้ไขทีละบทในไฟล์เดียวไม่ไหว และผู้ช่วย AI ต้องเลือกส่งเฉพาะบทที่เกี่ยวข้อง (เพดาน context) ซึ่งเป็นงานฝั่ง server. **เหตุผลที่ไม่ใช่เว็บแอปใหญ่:** ไม่มี state ที่ต้องแชร์ระหว่างผู้ใช้ ความคืบหน้าเก็บในเบราว์เซอร์พอ

| บทเรียน | `/b/{bookSlug}/{chapterSlug}` | เหมือนหน้าบทของ prototype ทุกประการ (ดูส่วนที่ 3) |

**Routing:** ใช้ URL จริง (history API หรือไฟล์ HTML ต่อบทที่ generate ไว้ล่วงหน้า) ไม่ใช่ซ่อน/โชว์ section แบบ prototype — เพราะต้องแชร์ลิงก์ตรงไปยังบทได้ และ Cloudflare Pages ในเฟส 2 เสิร์ฟไฟล์ static ได้ดีกว่า SPA

## 5. Navigation + Mobile Responsive (ข้อกำหนดบังคับ)

**Breakpoints**
- `≥ 861px` desktop: grid 250px rail + เนื้อหา max-width 72ch กลางจอ
- `≤ 860px` มือถือ/แท็บเล็ตแนวตั้ง: ซ่อน rail, แสดง `MobileTopbar` sticky บนสุด, เนื้อหาเต็มความกว้าง padding 18px
- ทดสอบที่ **360×740 (Android เล็ก), 390×844 (iPhone), 768×1024 (iPad), 1280×800** ทุกหน้า ทุกบท

**กฎที่ต้องผ่านบนมือถือ**
1. ไม่มี horizontal scroll ของ body เด็ดขาด — ตาราง/โค้ด/canvas ที่กว้างต้องอยู่ใน container ที่ `overflow-x:auto` ของตัวเอง
2. canvas ใน `UniverseWindow` ใช้ `width:100%; height:auto` และ **วาดด้วย viewBox/scale ตามความกว้างจริง** ตัวอักษรในแคนวาสต้องอ่านออกที่ความกว้าง 320px (ขั้นต่ำ 12px หลัง scale; ถ้าไม่พอให้ย้าย label ออกมาเป็น HTML ใต้แคนวาส)
3. slider (`input[type=range]`) สูงอย่างน้อย 44px ในพื้นที่แตะ; ชิป/ปุ่มทุกตัว hit area ≥ 44×44px
4. `.lens` (3 แว่น), `.three` (3 กฎ), `.phase`, `.step` เปลี่ยนเป็น 1 คอลัมน์ที่ ≤ 860px (prototype ทำไว้แล้วบางส่วน ให้ทำครบ)
5. `AskPanel` บนมือถือ = เต็มจอ (`inset:0; border-radius:0`) ไม่ใช่กล่องลอย; ช่องพิมพ์ต้องไม่ถูก keyboard บัง (ใช้ `100dvh` + `position:fixed` bottom)
6. `TermSheet` = bottom sheet เต็มความกว้าง max-height 75vh เลื่อนภายในได้
7. FAB ไม่ทับ `ChapterNav` และปุ่มส่งแบบฝึก — เพิ่ม padding-bottom ของ page ≥ 120px
8. ฟอนต์ body บนมือถือ 16–17px line-height 1.8 ห้ามเล็กกว่านี้ (ผู้อ่านหลายคนอายุ 50+)
9. รองรับ `prefers-reduced-motion` (หยุด animation loop ใช้ setTimeout ช้าๆ แทน) และ `prefers-color-scheme`
10. ทำงานได้บน Safari iOS 15+ และ Chrome Android — ห้ามใช้ feature ที่ Safari ไม่รองรับโดยไม่มี fallback

**ตำแหน่งปัจจุบัน:** เมื่อเข้า `/b/x/ch` rail ต้อง highlight บทนั้น, dropdown ต้องเลือกบทนั้น, และ AskPanel แสดง "บริบท: เล่ม… บทที่…"

## 6. Interaction / state

| สถานการณ์ | พฤติกรรม |
|---|---|
| กด `<dfn>` | เปิด TermSheet ทันที (ข้อมูลอยู่ในหน้าแล้ว ไม่มี network) ปิดด้วย ×, กดพื้นหลัง, Esc |
| กด "ถามเพิ่มเกี่ยวกับคำนี้" | ปิด sheet → เปิด AskPanel → ส่งคำถาม `ช่วยอธิบายคำว่า "{term}" ให้ละเอียดขึ้น พร้อมตัวอย่างในชีวิตประจำวัน` อัตโนมัติ |
| กดถาม | ข้อความผู้ใช้ขึ้นทันที → บับเบิลผู้ช่วย "กำลังคิด…" (italic) → stream ทีละส่วน (SSE) → เสร็จแล้วเปลี่ยนเป็นตัวปกติ |
| ถามซ้ำระหว่างรอ | ปุ่มส่ง disabled จนกว่าจะเสร็จ (busy flag) |
| ผู้ช่วยล้มเหลว | โชว์ข้อความไทยตาม error code (ดู 9.5) ห้าม retry อัตโนมัติ |
| ทำแบบฝึกแล้วกด "ให้ผู้ช่วยช่วยดู" | ถ้า textarea ว่าง → ข้อความ "ลองเขียนสักสองสามบรรทัดก่อน" (ไม่เรียก API) มิฉะนั้น stream feedback ลง `.feedback` |
| เปลี่ยนตัวเลือกในแบบฝึก | render 3 ขั้นใหม่ทันที ไม่มี animation |
| เข้าบท | scroll top, บันทึก `lastRoute` และ mark บทเป็น "เปิดแล้ว"; เลื่อนถึง `ChapterNav` = mark "อ่านจบ" |
| Empty state ชั้นหนังสือ | เล่มที่ `status=building` แสดงการ์ดจาง + ป้าย "กำลังสร้าง" กดได้ ไปหน้ารอสร้าง |

Loop แอนิเมชัน: `requestAnimationFrame` เฉพาะเมื่อ panel นั้นอยู่ใน viewport (IntersectionObserver) — prototype วาดตลอดเวลาที่หน้าเปิด ให้ปรับเพื่อประหยัดแบตมือถือ

## 8. ข้อมูลนำเข้า — Content pipeline (PDF → บทเรียน)

**Input:** PDF 9 เล่ม อยู่ที่ `content/source/bookNN-*.pdf` (ไม่ commit ลง git — ดูข้อห้าม)

**ขั้นตอน (script `pipeline/`):**
1. `extract.py` — `pdftotext` (poppler) แบบไม่ใช้ `-layout` → ไฟล์ `.txt`
2. `clean.py` — **ต้องมี** เพราะ PDF เล่มแรกฝังฟอนต์ที่ทำให้ตัวอักษรไทยซ้อนกัน (เช่น `หนัังสืือ`, `ไตรลัักษณ์์`, `พระพุุทธองค์์`) กฎ: ยุบตัวอักษรไทยที่ซ้ำติดกันเป็นตัวเดียว `re.sub(r'([฀-๿])\1+', r'\1', t)`, ลบ `�` และสระลอยที่ตามหลัง, ลบเลขหน้าที่อยู่บรรทัดเดี่ยว, รวมบรรทัดที่ถูกตัดกลางคำ. **ผลลัพธ์ต้องตรวจด้วยตาก่อนใช้** (ตัวอย่างผลลัพธ์ที่ผ่านแล้ว = `book01-…-cleaned.txt` ที่แนบมา แต่ยังมีคำที่ยุบเกินไป เช่น `ปัญา` ควรเป็น `ปัญญา`, `สัญา`→`สัญญา`, `อนัตา`→`อนัตตา`, `ธรม`→`ธรรม`, `กรม`→`กรรม`, `เซล์`→`เซลล์`, `นิพาน`→`นิพพาน` — ต้องมี **dictionary แก้คำที่มีตัวสะกดซ้ำโดยชอบ** ก่อน regex หรือหลัง regex ก็ได้ แต่ต้องทำ)
3. `split.py` — แยกบทจากสารบัญ (เลขไทย + ชื่อบท) → `content/books/{bookSlug}/raw/chNN.txt`
4. `author.py` — ส่งข้อความบทเข้า Claude API (model tier สูงสุดที่มี) พร้อม **กฎการเรียบเรียง 9.1** + ตัวอย่างบทที่ 1–2 จาก prototype เป็น few-shot → ได้ `chNN.json` ตาม data model ส่วนที่ 10
5. `terms.py` — รวม glossary ทุกบท → `glossary.json` ต่อเล่ม (dedupe ตาม `term`) และ auto-link `<dfn>` ในเนื้อหา (กฎ 9.2)
6. `build.js` — render JSON → HTML static ต่อบท + `index.json` (สารบัญย่อทั้งชุดสำหรับผู้ช่วย AI ดู 9.4)

**Human-in-the-loop:** ผลจาก `author.py` ต้องมีคนตรวจก่อน mark `status: ready` — ระบบต้องรองรับ `status: draft | ready | building` ต่อบท และหน้าเว็บแสดงเฉพาะ `ready` เป็น "อ่านได้"

**ภาพเคลื่อนไหวเฉพาะบท (UniverseWindow):** pipeline **ไม่** สร้างอัตโนมัติ — เป็น module JS เขียนมือต่อบท (`interactives/{bookSlug}/chNN.js`) export `{mount(el, opts), unmount()}`; บทที่ยังไม่มี ใช้ interactive กลาง `particles` (จากบทที่ 1 ของ prototype) โดยเปลี่ยนชุด object/คำอธิบายผ่าน JSON แทน

## 9. ⭐ BUSINESS LOGIC — หัวใจ

### 9.1 กฎการเรียบเรียงเนื้อหาบท (ใช้ใน `author.py` และตอนเขียนมือ)

เป้าหมาย: ผู้อ่านไม่มีพื้นทั้งธรรมะและวิทยาศาสตร์ อ่านจบบทแล้ว "เห็น" ไม่ใช่แค่ "รู้"

1. **ห้ามคัดลอกข้อความจากหนังสือ** ยกเว้น (ก) พุทธพจน์ที่หนังสือยกมา — ยกได้เต็มพร้อมบรรทัดที่มา (ข) วลีสั้น ≤ 12 คำเพื่ออ้างอิงจุดยืนผู้เขียน ใส่เครื่องหมายคำพูด — *เหตุผล:* หนังสือมีลิขสิทธิ์ คู่มือนี้คือ "คู่มือประกอบการอ่าน" ที่อธิบายด้วยคำของเราเอง
2. โครงบทตายตัว: `goal` (1 ประโยค "จบบทนี้คุณจะ…") → 2–4 `sections` (แต่ละ section มี h2 + 2–5 ย่อหน้า) → `interactive` 1 ชิ้น วางหลัง section ที่อธิบายกลไก → `quote` (ถ้าหนังสือมี) → `exercise` → `questions` 4 ข้อ
3. ทุกศัพท์เทคนิค (ทั้งสองสาย) ต้องถูกอธิบายในประโยคเดียวกันหรือประโยคถัดไป **ครั้งแรกที่ปรากฏในบท** แม้จะอยู่ใน glossary แล้วก็ตาม
4. ทุก section ต้องปิดด้วยการโยงกลับไตรลักษณ์ (หรือแนวคิดหลักของเล่มนั้น) เหมือนที่หนังสือทำ — ห้ามจบที่ข้อเท็จจริงวิทยาศาสตร์ลอยๆ
5. ต้องมี "ข้อผิดพลาดที่คนมักเข้าใจผิด" อย่างน้อย 1 จุดต่อบท (เช่น ทุกขัง ≠ ทุกข์ใจ) และมีกล่อง `callout` ที่ตอบคำถาม "ทำไม" อย่างน้อย 1 กล่องเมื่อหนังสือมีเหตุผลนั้น
6. ตัวเลขวิทยาศาสตร์ใช้ค่าปัจจุบันที่ยอมรับ และเมื่อหนังสือใช้ค่าเก่า ให้ใส่ทั้งสองแบบ `(หนังสือเขียน 15,000 ล้านปี ค่าปัจจุบัน ~13,800 ล้านปี)` — *เหตุผล:* ผู้อ่านจะเปิดหนังสือเทียบ ถ้าตัวเลขไม่ตรงจะสับสนว่าใครผิด
7. เรื่องที่วิทยาศาสตร์ยังถกเถียง (เช่น จิตควอนตัม/ไมโครทิวบูล) ต้องระบุว่า "เป็นสมมติฐาน" ห้ามเขียนเหมือนข้อสรุป — แต่ต้องเคารพจุดยืนหนังสือ ไม่ต้องหักล้าง
8. น้ำเสียง: เพื่อนที่รู้เรื่องเล่าให้ฟัง ประโยคสั้น ไม่มี bullet ในเนื้อหา (bullet ใช้ได้เฉพาะรายการธาตุ/ชนิด) ไม่ใช้ "ท่าน/ผู้อ่านพึง" ใช้ "คุณ/เรา"
9. ความยาวต่อบท 900–1,400 คำ (ไม่รวม interactive/exercise) — สั้นกว่านี้ตื้น ยาวกว่านี้คนทั่วไปไม่จบ
10. `exercise` ต้องมี 4 ตัวเลือก × 3 ขั้น ตัวอย่างต้องเป็น **ของใกล้ตัวคนไทยปัจจุบัน** (รถ บ้าน โทรศัพท์ ชื่อเสียง ความสัมพันธ์ ใบหน้า) ไม่ใช่ตัวอย่างในคัมภีร์
11. `questions` 4 ข้อ ต้องเป็นคำถามที่ **คนอ่านบทนี้แล้วสงสัยจริง** ไม่ใช่คำถามท่องจำ ("ถ้าทุกอย่างไม่เที่ยงแล้วจะตั้งใจทำอะไรไปทำไม" ✔ / "ไตรลักษณ์มีกี่ข้อ" ✘)

### 9.2 กฎ glossary และ auto-link

- `term` ต้องมี `kind: "ธรรมะ" | "วิทยาศาสตร์"`, `alt` (บาลี/อังกฤษ), `def` 2–4 ประโยค ภาษาคนธรรมดา ประโยคสุดท้ายโยงกับหนังสือหรือชีวิตจริง
- auto-link: ในเนื้อหา HTML ห่อ **เฉพาะการปรากฏครั้งแรกของศัพท์ในแต่ละ section** ด้วย `<dfn data-term="…">` — ไม่ห่อทุกครั้ง (รกและกดพลาดบนมือถือ) ไม่ห่อภายใน `quote`, หัวข้อ, และ readout ของ interactive
- จับคู่แบบ longest-match ก่อน (`ขันธ์ ๕` ก่อน `ขันธ์`) และ **ห้ามห่อคำที่อยู่ในคำอื่น** (เช่น `สติ` ใน `สติปัญญา`) ใช้ขอบเขตคำไทยจากรายการ term เอง (เช็คตัวอักษรไทยหน้า/หลัง)
- glossary ของทุกเล่มรวมกันเป็นชุดเดียว ถ้าซ้ำ term ให้ใช้ def จากเล่มที่ปรากฏก่อน แต่บันทึก `books[]` ที่มีคำนั้น

### 9.3 กฎการตอบของผู้ช่วย AI (system prompt — ใช้ข้อความนี้ตรงๆ)

```
คุณคือผู้ช่วยอธิบายหนังสือชุด "{ชื่อชุด}" ให้คนทั่วไปที่ไม่มีพื้นฐานทั้งธรรมะและวิทยาศาสตร์
กติกา:
- ตอบเป็นภาษาไทยที่อ่านง่าย เหมือนเพื่อนที่รู้เรื่องนี้เล่าให้ฟัง ไม่ใช้ศัพท์โดยไม่อธิบาย
- ยาวไม่เกิน 6-8 ประโยค เว้นแต่ถูกขอให้ละเอียด ห้ามใช้ bullet หรือหัวข้อ ให้เขียนเป็นย่อหน้า
- อ้างอิงว่าเรื่องนี้อยู่ "เล่ม X บทที่ Y" ของหนังสือเสมอเมื่อเกี่ยวข้อง
- ยึดเนื้อหาและจุดยืนของหนังสือเป็นหลัก ถ้าคำถามเกินขอบเขตหนังสือหรือเป็นเรื่องที่วิทยาศาสตร์ยังถกเถียง ให้บอกตรงๆ ว่าหนังสือว่าอย่างไร และวิทยาศาสตร์ปัจจุบันว่าอย่างไร
- ปิดท้ายด้วยการโยงกลับมาที่ชีวิตประจำวันของผู้ถาม 1 ประโยค เมื่อทำได้อย่างเป็นธรรมชาติ
- ห้ามแต่งพุทธพจน์ขึ้นเอง ถ้าไม่แน่ใจให้บอกว่าไม่แน่ใจ
- ห้ามให้คำแนะนำทางการแพทย์ กฎหมาย หรือการเงิน ถ้าถูกถาม ให้ชวนกลับมาที่มุมมองของหนังสือ
- ถ้าคำถามไม่เกี่ยวกับหนังสือหรือธรรมะ/วิทยาศาสตร์เลย ตอบสั้นๆ ว่าช่วยได้เฉพาะเรื่องในหนังสือชุดนี้
```

Prompt สำหรับ feedback แบบฝึก (แยกต่างหาก): ใช้ข้อความจาก prototype ฟังก์ชัน `data-ai-feedback` — "ชมสิ่งที่เห็นได้จริง แล้วชี้ 1 จุดที่ยังเป็น 'ความรู้ที่ท่องมา' มากกว่า 'การเห็น' พร้อมคำถามชวนให้มองลึกอีกขั้น 4–6 ประโยค ห้าม bullet"

### 9.4 การเลือกบริบทส่งให้ AI (retrieval — ทำฝั่ง proxy)

ทุก request จากหน้าเว็บส่ง `{bookSlug, chapterSlug, turns[]}` proxy ประกอบ context ตามลำดับนี้ (จำกัดรวม ≤ 60,000 tokens โดยประมาณ ≈ 150,000 ตัวอักษรไทย):

1. system prompt (9.3)
2. `index.json` ทั้งชุด = ทุกเล่ม ทุกบท: ชื่อ + `summary` 2–3 ประโยค (เป็นแผนที่ให้ AI รู้ว่าอะไรอยู่ไหน) — ≈ 80 บท × 300 ตัวอักษร = เล็ก
3. **บทปัจจุบันเต็ม** (เนื้อหา JSON แปลงเป็น text + glossary ของบท + exercise)
4. บทก่อนหน้าและถัดไปในเล่มเดียวกัน **เฉพาะ `summary` + `keyPoints`** (ไม่เต็ม)
5. ถ้า `turns` มีคำถามที่ตรงกับ `keywords[]` ของบทอื่น (match ≥ 2 keyword) ให้แนบ `keyPoints` ของบทนั้นเพิ่ม สูงสุด 3 บท
6. `turns` 8 คู่ล่าสุด (ตัดเก่าทิ้ง)

*เหตุผล:* ไม่ต้องใช้ vector DB — คำถามเกือบทั้งหมดถามเรื่องบทที่กำลังอ่าน และสารบัญย่อทำให้ AI ชี้ไปบทอื่นได้ถูก ค่าใช้จ่ายต่อคำถามควบคุมได้ ถ้าเฟส 2 พบว่าไม่พอค่อยเพิ่ม embedding

ใช้ **prompt caching** กับส่วนที่ 1–2 (คงที่ทุกคำถาม) และส่วนที่ 3 (คงที่ตลอดที่อยู่บทเดิม)

### 9.5 การป้องกันค่าใช้จ่ายและ error (proxy)

- Rate limit: **30 คำถาม / IP / วัน** และ **5 คำถาม / IP / นาที** (ค่าตั้งใน env) เกินแล้วตอบ `429` พร้อมข้อความไทย "วันนี้ถามครบโควตาแล้ว พรุ่งนี้ถามต่อได้"
- จำกัดความยาวคำถาม 1,000 ตัวอักษร, textarea แบบฝึก 2,000 ตัวอักษร
- `max\_tokens` คำตอบ 800, feedback 500
- แปลง error → ข้อความไทย: `429`→ข้างต้น, `401/403`→"ระบบยังไม่ได้ตั้งค่า key", `5xx`/timeout→"ตอบไม่ได้ในตอนนี้ ลองใหม่อีกครั้ง", network→"ไม่มีอินเทอร์เน็ต" — **ห้าม retry อัตโนมัติจากหน้าเว็บ**
- log เฉพาะ `timestamp, bookSlug, chapterSlug, inputTokens, outputTokens, latency` **ไม่ log ข้อความคำถาม** (ความเป็นส่วนตัว)
- ตั้ง spend limit ในบัญชี Anthropic แยกจาก code (เตือนผู้ใช้ใน README)

### 9.6 ความคืบหน้าผู้ใช้ (client-only)

localStorage key `dsl.progress` = `{ lastRoute, chapters: { "book/ch": { opened: ts, finished: ts|null } } }`; `dsl.turns.{book}` = ประวัติแชทต่อเล่ม (สูงสุด 40 ข้อความ); ทุกการอ่าน/เขียน wrap try/catch — private mode ต้องไม่พัง. **ไม่มี server-side state ในเฟส 1–2**

### 9.7 กฎการนับ "อ่านจบ"

`finished` เมื่อ `ChapterNav` เข้า viewport ≥ 50% เป็นเวลา ≥ 2 วินาที (กันเลื่อนผ่านเร็วๆ) หน้าแผนที่แสดง ✓ และหน้าชั้นหนังสือแสดง `finished/total`

## 10. Data model (ไฟล์ JSON — ไม่มี DB)

```
Book {
 slug: string // "trilaksana-quantum"
 order: number // 1..9
 title: string // "ไตรลักษณ์ในควอนตัม"
 author: string
 blurb: string // คำโปรย 2-3 ประโยค (เขียนใหม่)
 coreIdeas: Idea[3] // กล่อง 3 ใบบนหน้าแผนที่ {label, pali?, text}
 status: "ready"|"building"
 chapters: ChapterMeta[]
}
ChapterMeta { slug, order, thaiNum:"๑", title, sub, status }

Chapter {
 book: slug, slug, order, thaiNum, title, sub
 status: "draft"|"ready"|"building"
 goal: string
 summary: string // 2-3 ประโยค (ใช้ใน index.json)
 keyPoints: string[5..8] // ประโยคสั้น (ใช้ใน retrieval)
 keywords: string[8..15] // คำค้น (ใช้ใน retrieval 9.4 ข้อ 5)
 sections: Section[] // { h2, paragraphs: string[] (HTML inline: <b>, <i>, <dfn>) , callout?: {label, text}, bullets?: string[] }
 interactive: { module: string, position: number /* หลัง section ที่เท่าไหร่ */, title, intro, config: object }
 quote?: { text, source }
 exercise: { title, intro, columns:[{label,sub}] x3, options:[{name, steps:[s1,s2,s3]}] x4, prompt, placeholder }
 questions: string[4]
 suggestions: string[3] // สำหรับ AskPanel
 terms: Term[] // ศัพท์ที่ปรากฏในบทนี้ (subset ของ glossary)
}
Term { term, kind:"ธรรมะ"|"วิทยาศาสตร์", alt, def, books: slug[] }

index.json = { books: [{slug,title,chapters:[{slug,thaiNum,title,summary}]}] }
```

**Seed ที่ต้องใช้จริง (มีในไฟล์แนบ):** บทที่ 1 และ 2 ของเล่มแรก ให้ **ดึงจาก `prototype-artifact.html`** (ข้อความ, GLOSS 30 คำ, IX1\_OBJ 5 ชุด, IX2\_LV 6 ระดับ, exercise 2 ชุด, questions, SUGG) แปลงเป็น `ch01.json`, `ch02.json` **ตรงตามต้นฉบับ ห้ามเขียนใหม่** — นี่คือมาตรฐานคุณภาพ; `BOOK\_KNOWLEDGE` ใน prototype ใช้เป็นต้นแบบของ `summary`+`keyPoints` ของบทที่ 3–9 ของเล่มแรก

- **ที่รัน:** Ubuntu server ที่บ้าน, Docker Compose, เข้าถึงผ่าน Tailscale (`http://<tailscale-hostname>:8080`) — ไม่เปิด port สาธารณะ ไม่ต้องมี HTTPS/โดเมน
- **ผู้ใช้:** เจ้าของ + ครอบครัว, อุปกรณ์หลักคือมือถือ
- **ระบบที่เชื่อม:** Anthropic Messages API เท่านั้น (streaming)
- **Deliverable:** เล่มแรกครบ 9 บท `status: ready` (บท 1–2 จาก prototype, บท 3–9 ผ่าน pipeline + ตรวจ), interactive เขียนมืออย่างน้อยบท 1, 2, 3 (สายโซ่ขันธ์ ๕ ที่กด "ใส่สติ" ได้), 4 (สไลเดอร์มวลดาว → แคระขาว/นิวตรอน/หลุมดำ), 9 (เซลล์เกิดดับทั้งร่าง); บทอื่นใช้ `particles` กลาง; หน้าชั้นหนังสือแสดงอีก 8 เล่มเป็น "กำลังสร้าง"; pipeline รันได้ end-to-end กับ PDF เล่มแรกแล้ว

### เฟส 2 (ไม่ต้องทำในรอบนี้ — ออกแบบให้รองรับ)
- รัน pipeline กับอีก 8 เล่ม + ตรวจ; interactive เพิ่มตามบทที่ "ต้องเห็นถึงจะเข้าใจ"
- Deploy `web/public` ขึ้น **Cloudflare Pages** และย้าย proxy เป็น **Pages Functions** (โค้ด proxy ต้องเขียนให้ไม่ผูกกับ Node API เฉพาะ เช่น ใช้ `fetch` + Web Streams ไม่ใช้ `fs`) — *เหตุผล:* ให้โค้ดชุดเดียวรันได้ทั้งบ้านและ Cloudflare
- self-host fonts, เพิ่ม embedding ถ้า retrieval 9.4 ไม่พอ, เพิ่ม share link ต่อบท (OG image)

### ข้อห้าม (พร้อมเหตุผล)
1. **ห้ามใส่ API key ในไฟล์ฝั่งเว็บหรือ commit ลง git** — ทุกคำถามต้องผ่าน proxy เท่านั้น (เว็บจะถูกแชร์สาธารณะในเฟส 2)
2. **ห้ามเสิร์ฟหรือ commit PDF ต้นฉบับ และห้ามใส่ข้อความเต็มของหนังสือลงหน้าเว็บ** — ลิขสิทธิ์ผู้เขียน คู่มือนี้อธิบายด้วยคำของเราเอง (ยกเว้นตาม 9.1 ข้อ 1) ข้อความ raw ใช้เฉพาะใน pipeline และใน context ของ proxy ฝั่ง server
3. **ห้ามให้ AI สร้างเนื้อหาบทแล้ว mark `ready` อัตโนมัติ** — ต้องผ่านคนตรวจ เพราะเรื่องธรรมะและตัวเลขวิทยาศาสตร์ผิดแล้วเสียความน่าเชื่อถือทั้งระบบ
4. **ห้ามข้ามขั้น clean ของ pipeline** — PDF ชุดนี้มีตัวอักษรไทยซ้อน ถ้าส่งตรงให้ AI จะได้ศัพท์ผิดๆ กระจายไปทั้งเล่ม
5. **ห้ามเปลี่ยน UniverseWindow ให้เป็นธีมสว่างตาม light mode** — เป็นการออกแบบตั้งใจ (กระดาษ = อ่าน, ความมืด = หน้าต่างมองจักรวาล)
6. **ห้ามใช้ `window.claude` / capability ของ Artifact** — prototype ใช้ `claude.use("sample")` ซึ่งมีเฉพาะใน claude.ai; ระบบจริงเรียก `/api/ask` เท่านั้น
7. **ห้าม retry API อัตโนมัติ และห้ามเรียก API ตอนโหลดหน้า** — เรียกเฉพาะเมื่อผู้ใช้กดถาม/กดให้ช่วยดู
8. **ห้ามใช้ bullet/หัวข้อในเนื้อหาบทและในคำตอบผู้ช่วย** — น้ำเสียงของงานนี้คือการเล่า ไม่ใช่สไลด์
9. **ห้าม auto-link `<dfn>` ทุกครั้งที่คำปรากฏ** — ครั้งแรกต่อ section เท่านั้น (9.2)
